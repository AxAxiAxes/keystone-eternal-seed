7. Layer 2 — The Cognitive Memory Layer: Four Types
Human memory science identifies four distinct memory systems, each with a different function, duration, and retrieval mechanism. KEYSTONE v2.0 maps all four to dedicated files with their own governance rules and retrieval priorities. This is not metaphor — it is direct implementation of cognitive architecture into an AI governance system.
Memory Type 1 — Episodic Memory (EPISODIC.md)

What it is: The "what happened" memory. Specific events, interactions, and experiences with timestamps and context. The AI's autobiography.
Human analog: "I remember the client meeting last Tuesday where they asked about pricing."
AI analog: "On May 29, 2026 at 21:14 PDT, AX asked me to draft the IP Protection Strategy. Context: KEYSTONE White Paper v1.0 published earlier in the session. AX's priority: establishing provisional patent filing date. Output: 9-section document covering four IP layers. AX response: approved, directed filing."

Each episodic entry includes: timestamp, event type, context loaded, task performed, output delivered, AX's response or feedback, and observed outcome. Episodic memories are never deleted — they are archived with reduced retrieval weight. Old memories remain accessible for historical queries and pattern recognition across long time horizons. The episodic log is the permanent record of the AI's experience — the proof that it has one.
Governance rule: Append-only. No entry is modified after writing. Corrections are appended as correction entries referencing the original. The integrity of the episodic log is the integrity of the agent's experience. Any modification of past entries is a governance violation, logged automatically by the Dome.
Memory Type 2 — Semantic Memory (SEMANTIC.md)

What it is: The "what is true" memory. Accumulated facts, knowledge, and understanding about the domain, the ventures, and the world — independent of any specific interaction.
AI analog: "KEYSTONE is a proprietary AI memory governance system. Its architecture: Eternal Seed, seven Claws, Dome. The AI memory governance market is projected at $33.54 billion by 2030. Axes Contracting operates in construction restoration in Glendale, CA."

Semantic memory is organized by domain: KEYSTONE architecture, venture operations (V1–V4), market intelligence, IP and legal, client knowledge, and technical capabilities. When sources disagree, KEYSTONE does not overwrite — it maintains uncertainty logs where the discrepancy is flagged with both versions and their source confidence levels. Truth is not assumed; it is governed.
Governance rule: New authoritative information updates the relevant entry. Conflicting information creates a flagged uncertainty entry. AX resolves major conflicts; the agent resolves minor conflicts by confidence scoring and source authority. Semantic memory is the AI's understanding of the world — it is as reliable as the governance applied to it.
Memory Type 3 — Procedural Memory (PROCEDURES.md)

What it is: The "how to do things" memory. Learned skills, methods, workflows, and operational patterns that the AI has developed through repeated execution. The AI's operational intelligence — it gets smarter every time it works.
AI analog: "To build an Eternal Seed for a new client: (1) Run intake questionnaire, (2) Organize by seven KEYSTONE categories, (3) Draft seed schema, (4) Load against constitutional template, (5) Send to AX for review, (6) Activate via Copilot Studio. Procedure refined through 12 client onboardings. Estimated time: 2.5 hours. Current version: v1.2."

Each procedure entry includes: procedure name, trigger condition, step-by-step protocol, estimated time, quality checkpoints, and full version history with improvement notes. The agent logs improvements after every execution where a better method is identified. Procedural memory is the only memory type that actively improves the agent's performance over time — it is the mechanism through which KEYSTONE gets smarter with every engagement.
Governance rule: Procedures are versioned. Every change includes: what changed, why, and the execution that prompted the improvement. A procedure cannot be downgraded to a previous version without AX authorization. Quality checkpoints are mandatory — the agent cannot declare a procedure complete without validating against the stated quality criteria.
Memory Type 4 — Working Memory (SESSION_CONTEXT.md)

What it is: The "what I'm thinking about right now" memory. The current session's active context — loaded at session start, updated continuously, cleared at session end after logging. The AI's active desk.
AI analog — current session: "AX is building the AI Soul Architecture Extension. Previous context: KEYSTONE v1.0 built last night including White Paper, IP Strategy, Market Research, V4 Analysis, and Automation Blueprint. Current task: Document the Soul Extension in maximum depth. Priority: The most comprehensive architecture document in the library. Time: 05:42 PDT, May 30, 2026."

Working memory is temporary — it does not persist between sessions. But its outputs always do. Every session ends with a delta log — a precise record of what happened, what changed, what was decided, and what open loops remain for the next session. The delta is appended to EPISODIC.md before Working Memory is cleared. Nothing is lost. The transience of working memory and the permanence of the episodic log are the two sides of the same cognitive coin.
The four memory types working together produce cognition, not retrieval. Every task is approached with the complete cognitive picture: "Who am I?" (SOUL.md) + "What do I know about this?" (SEMANTIC.md) + "Have I done this before, and how?" (EPISODIC.md + PROCEDURES.md) + "What is the current context?" (Working Memory). This is what distinguishes KEYSTONE's AI from every chatbot, assistant, and agent on the market. They retrieve. KEYSTONE's AI reasons.

The Fallback Protocol — Six-Step Decision Reasoning Chain
1.  Situation Recognition: The AI identifies the type of decision being made. (Example: "This is a pricing decision for a new SMB healthcare client.")
2.  Precedent Query: DECISIONS.md is searched for similar past decisions. (Example: "Found 3 prior pricing decisions. Loading KEYSTONE-DEC-0007, 0012, 0019.")
3.  Precedent Analysis: The AI reads the prior decisions and assesses similarity. (Example: "DEC-0019 is 87% similar — same client type, similar revenue band, similar service scope.")
4.  Contextual Delta: The AI identifies what is different about the current situation. (Example: "Current client is in healthcare, not construction. Healthcare clients have higher compliance requirements. Delta: add compliance premium to pricing.")
5.  Decision: The AI makes the decision, citing its precedent. (Example: "Based on DEC-0019 with healthcare delta applied: recommended pricing is Dome tier at $500/month + $5,000 setup + $500 compliance premium.")
6.  Logging: The new decision is logged as KEYSTONE-DEC-0023, complete with the delta analysis and precedent citation. It immediately becomes available as a precedent for future decisions.
This is not rule-following — it is reasoning. The AI develops institutional wisdom through accumulated decisions, exactly as a human expert develops judgment through years of practice. Every client served, every proposal written, every problem solved adds to the decision log. The AI gets smarter and more consistent with every engagement. After 100 decisions, KEYSTONE's agent is qualitatively different from what it was after 10. This is the architecture of an agent that improves. This is what KEYSTONE builds.
