# AXI GitHub access

**Status:** Read and founder-approved write access (comment, open PR, merge PR). Off by default. Every write action is subject to GitHub's own branch protection and required status checks on the target repository.

## What this is

`apps/axiom-engine` can report GitHub pull-request, issue, and repository
status through `GithubStatusService`, and — as of 2026-09-15, with explicit
founder approval ("yes all capabilities approved") — can also comment on
issues/PRs, open pull requests, and merge pull requests.

- **Off by default.** Until an operator sets both `AXIOM_GITHUB_TOKEN` and
  `AXIOM_GITHUB_REPO`, `GET /system/github` reports `{ "configured": false }`
  and every other GitHub route fails closed with `503`.
- **AXI cannot create its own credentials.** A token must be generated by an
  authorized human in GitHub's own settings (Settings → Developer settings →
  Personal access tokens → **Fine-grained tokens**, scoped to exactly one
  repository, with "Pull requests" and "Issues" **read and write**
  permissions granted) and supplied to the engine out-of-band, the same way
  `OPENAI_API_KEY` is supplied. This document does not, and cannot, generate
  or embed that token.
- **GitHub's own protections remain the real safety backstop.** Branch
  protection and required CI checks already configured on
  `axaxiaxes-axiom-monorepo` are enforced server-side by GitHub itself, not
  by this service. A merge request that GitHub would reject for a human
  caller (failing/pending required checks, unmet review requirements) is
  rejected here in exactly the same way — this service has no way to
  bypass those protections.
- **AXI does not act on its own initiative.** These are on-demand API
  routes: something must explicitly call them (an operator, a script, or a
  future automation task routed through the existing approval-gated
  pipeline). There is no scheduler or autonomous loop in this service that
  decides by itself to comment, open, or merge anything.

## Routes

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/system/github` | open | Reports whether GitHub access is configured and its declared scope. Never returns the token. |
| `GET` | `/system/github/repository` | admin | Repository name, default branch, visibility, open-issue count. |
| `GET` | `/system/github/pull-requests` | admin | Lists pull requests (`?state=open\|closed\|all`, `?limit=1-100`). |
| `GET` | `/system/github/issues` | admin | Lists issues, excluding pull requests (GitHub's issues endpoint otherwise includes them). |
| `POST` | `/system/github/issues/:number/comments` | admin | Posts a comment (`{ "body": "..." }`) on an issue or pull request. |
| `POST` | `/system/github/pull-requests` | admin | Opens a pull request (`{ "title", "head", "base", "body"? }`). |
| `PUT` | `/system/github/pull-requests/:number/merge` | admin | Merges a pull request (`{ "mergeMethod"?: "merge"\|"squash"\|"rebase", "commitTitle"? }`, default `squash`). Fails with GitHub's own rejection reason (e.g. a pending required check) surfaced as the error message. |

## History

- **2026-09-15 (read-only):** shipped read-only status/PRs/issues/repository
  visibility. Full write/merge access was deliberately declined pending a
  separate founder decision.
- **2026-09-15 (write, founder-approved):** founder explicitly approved
  "all capabilities" for AXI's GitHub access. Comment, open-PR, and merge-PR
  routes were added on top of the existing admin-gated, off-by-default,
  human-supplied-token foundation. No change was made to how the token is
  obtained (still requires a human to generate and supply it) or to
  `axaxiaxes-axiom-monorepo`'s branch protection/required-checks
  configuration, which remains the operative safety backstop for merges.
