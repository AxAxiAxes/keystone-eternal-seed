# AXI GitHub access

**Status:** Read-only visibility only. Off by default. No write access exists or is planned without a separate, explicit founder decision.

## What this is

`apps/axiom-engine` can optionally report GitHub pull-request, issue, and
repository status through `GithubStatusService`. It exists so AXI's own
dashboards/automation can see repository activity without a human manually
checking GitHub. It is intentionally the smallest useful slice of "GitHub
access":

- **Read-only.** Every call is an HTTP `GET` to the GitHub REST API. There is
  no code path that issues a `POST`, `PATCH`, `PUT`, or `DELETE` request.
  AXI cannot open, comment on, approve, merge, or close a pull request or
  issue, cannot push a commit, and cannot change any repository setting.
- **Off by default.** Until an operator sets both `AXIOM_GITHUB_TOKEN` and
  `AXIOM_GITHUB_REPO`, `GET /system/github` reports `{ "configured": false }`
  and every other GitHub route fails closed with `503`.
- **AXI cannot create its own credentials.** A token must be generated by an
  authorized human in GitHub's own settings (Settings → Developer settings →
  Personal access tokens → **Fine-grained tokens**, scoped to exactly one
  repository, with only the "Pull requests" and "Issues" **read** permissions
  granted) and supplied to the engine out-of-band, the same way
  `OPENAI_API_KEY` is supplied. This document does not, and cannot, generate
  or embed that token.

## Routes

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/system/github` | open | Reports whether GitHub access is configured and its declared scope. Never returns the token. |
| `GET` | `/system/github/repository` | admin | Repository name, default branch, visibility, open-issue count. |
| `GET` | `/system/github/pull-requests` | admin | Lists pull requests (`?state=open\|closed\|all`, `?limit=1-100`). |
| `GET` | `/system/github/issues` | admin | Lists issues, excluding pull requests (GitHub's issues endpoint otherwise includes them). |

## Explicitly out of scope

Full "commit and merge like a CLI session" access (what this session itself
has, via `git`/`gh`) was **not** implemented. That would let a running,
internet-reachable service push code and merge pull requests unattended --
a materially different risk profile than read-only status. If that is
actually wanted, it needs its own explicit founder decision covering:

- which repository/repositories, and whether it's scoped to a bot account,
- whether it can only open PRs (still requiring human/CI approval to merge)
  or can merge directly,
- how the credential is rotated/revoked if compromised,
- whether branch protection and required CI checks (already configured on
  `axaxiaxes-axiom-monorepo`) remain the actual safety backstop regardless
  of what AXI is technically capable of requesting.

Until that decision is made, this document and the shipped code intentionally
stop at read-only visibility.
