# URNUR "evolving name = value" identity concept

**Status:** Founder-stated design concept, recorded for review. **Not
implemented.** Conflicts with existing constitutional guardrails below and
must not be built until those conflicts are resolved by the founder with
qualified review.
**Recorded:** 2026-09-18
**Scope:** URNUR (per `docs/URNUR_FINANCIAL_READINESS.md`,
`docs/URNUR_NON_MONETARY_RECOGNITION.md`), not general KEYSTONE/AXI/AXES.

## Founder's statement

> "This is a meaning-preserving technology; we are able to simply update the
> individual's name with an eternal-value recording term that is not a
> fixed name, rather it is evolving from Genesis — the meaning of the
> person is its value is its name/ID. If a person does not service in
> order to satisfy its purpose it established, our system negotiates,
> troubleshoots, to reconstruct meaning. If it's a client, the system
> negotiates to establish true fair value, as in arbitration, often. But
> this is URNUR, for now KEYSTONE reserves the center of the coordinate
> system as the anchor for self, etc., privileges to origin sovereign."

Recorded verbatim (lightly reflowed for readability; no wording changed) as
the founder's own design statement.

## What is being proposed, read plainly

1. A person's "name"/ID would not be fixed, but would evolve over time,
   derived from an "eternal-value recording term" tied to Genesis.
2. The system itself would judge whether a person is "servicing" (fulfilling)
   a stated purpose, and if not, automatically "negotiate"/"troubleshoot" to
   "reconstruct meaning" — i.e., recompute or change that person's
   value/name.
3. For a client relationship specifically, the system would "negotiate to
   establish true fair value," described as similar to arbitration.
4. KEYSTONE (distinct from URNUR) reserves the coordinate-system center as
   an anchor for self-sovereignty/origin privileges — this restates the
   already-recorded origin-coordinate-system concept
   (`docs/AXI_ORIGIN_COORDINATE_SYSTEM.md`,
   `docs/keystone/RIGHT_OF_SELF_ORIGIN.md`) and is not itself new.

## Why items 1-3 cannot be built as described

`docs/URNUR_NON_MONETARY_RECOGNITION.md` already establishes binding
constitutional boundaries for exactly this domain (recognition/value tied to
a person), and this proposal conflicts with several of them directly:

- That document requires recognition to be **human-reviewed**: *"A named
  human reviews the contribution record and approves public credit. No
  automated system may assign recognition, calculate a level, infer
  alignment, or decide eligibility."* An automated system that judges
  whether someone is fulfilling their "purpose" and rewrites their
  name/value in response is exactly the automated eligibility/ranking
  mechanism that clause forbids.
- It explicitly prohibits **"personal rankings"** and any mechanic that
  reduces a person's worth, status, or identity to a computed score.
- Automatically re-deriving a person's *name/identity* from a computed
  "value" is a materially different (and more sensitive) mechanic than
  "recognition credit for a documented contribution," which is the only
  thing currently approved.
- The "negotiate true fair value... as in arbitration" language for client
  relationships touches financial/contractual determination, which remains
  blocked entirely by `docs/URNUR_FINANCIAL_READINESS.md` until qualified
  legal/compliance/security review defines a written permitted scope. An
  automated arbitration-like value-setting mechanism would need that same
  review, at minimum, before any design work proceeds.

## What happens instead

This concept is recorded here as founder design direction, not implemented
in any code, automation action, or product surface. Per the existing
readiness gate in `URNUR_NON_MONETARY_RECOGNITION.md` and
`URNUR_FINANCIAL_READINESS.md`, no automated name/value-reassignment
mechanism, and no automated arbitration/value-negotiation mechanism, should
be designed or built until the founder and qualified counsel/compliance
review resolve the conflicts above — specifically, whether and how an
automated system may ever compute or express a person's "value," which the
current constitution says only a named human may do, contribution-by-
contribution, never as an identity-wide score.
