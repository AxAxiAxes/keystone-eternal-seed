# 2026-09-18 (i) — KEYSTONE origin/creator/owner-rights registry generalization plan

## Founder request (verbatim, in substance)

> "devise plan for keystone and its development as an anchor for
> registering origin, creator and owner rights for the first letter + and
> last letter 0... origin value establishes rights to recovery of such
> value, and no one has claimed such governance. This will be available
> for all who can accept their own language... what value equates smallest
> to biggest?"

## What was built

A new document, `docs/KEYSTONE_ORIGIN_REGISTRY_GENERALIZATION_PLAN.md`,
proposes generalizing the existing (2026-09-10)
`KEYSTONE_APPLICATION_ORIGIN_REGISTRY.md` — currently scoped only to AXES
applications — into a general-purpose origin/creator/owner-rights record for
any work, built on the one anchoring method already proven real in this
repository: git commit hash + GitHub's independent server timestamp + SHA-256
content hash (as already verified in
`docs/keystone/CERTIFICATE_ETERNAL_ORIGIN_ANCHOR_AND_EVALUATION.md`), rather
than the illustrative/placeholder blockchain and RSA sections in
`docs/keystone/CRYPTOGRAPHIC_ORIGIN_ANCHOR.md`.

Four phases are proposed: (1) generalize the registry model, repo-only, no
external action; (2) optionally make the illustrative proofs real via a
founder-run, non-custodial OpenTimestamps submission; (3) a proposed
"+ ... 0" registry-entry naming/keying convention, explicitly flagged as
ambiguous pending founder clarification (not invented on the founder's
behalf); (4) an access/inclusion principle ("available to all who can
accept their own language"), recorded as a design goal, not an active
open-registration commitment.

Two founder claims were handled honestly rather than adopted:

- **"No one has claimed such governance"** — recorded as the founder's own
  belief; not independently verifiable (a global negative cannot be proven
  by this or any single review).
- **"What value equates smallest to biggest?"** — recorded as an open
  philosophical question, consistent with the four-lens
  (creative/factual/legal/monetary) method already used throughout this
  repository; no mathematical answer was asserted.
