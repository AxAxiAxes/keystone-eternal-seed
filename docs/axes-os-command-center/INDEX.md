# AXES OS Command Center — Document Index

**What this is:** a single organized, read-only *copy collection* of every
document currently in this repository's `docs/` tree (plus the root-level
`README.md`, `PROJECT_TIMELINE.md`, `AGENTS.md`, and `NOTICE.md`), grouped
by category so the full paper trail of the project can be reviewed from one
place. **Nothing was moved or deleted.** Every file here is a copy; the
original, canonical, editable version of every document still lives at its
original path (each section below links back to the source folder). If you
need to edit a document, edit the original — this tree exists for review and
navigation only, and can be regenerated at any time by re-running
`scripts/organize-axes-os-command-center.js`.

## Why this exists — the AXES OS framing

This index is built for **AXES OS**: the founder's stated direction for this
whole portfolio to converge into one **OS + AI + Web + App production
company** — not a loose collection of side projects, but a single platform
company (AXES Contracting as the legal/operating entity; AXIOM as its AI;
KEYSTONE as its architecture/governance layer; XIIOM, Axaxar, and the other
active domains as its product surfaces). Every category below is labeled
with how it feeds that goal, so future work — including future automated
review — treats "is this useful to AXES OS: an OS, AI, web, and app
production company" as the standing question when deciding what to build,
consolidate, or retire.

## How this was built

Generated by `scripts/organize-axes-os-command-center.js`, which:
1. Walks `docs/` (plus four root-level files) read-only.
2. Classifies each file into exactly one category, using folder-based
   routing for bulk sources (memory, patents, fixtures, assets, status,
   activation) and filename-pattern rules for everything else.
3. Copies (never moves) each file into its category folder here, preserving
   any subfolder structure needed to avoid filename collisions (e.g. the
   two `README.md` files under `docs/keystone/assets/`).
4. A small number of files that didn't match any rule were manually
   triaged into the most appropriate category above.
